# rigged_poc

Educational proof of concept of the rigged repository attack. A fake
recruiter sends a ZIP archive containing a booby trapped local git
repository. Unpacking the archive is inert. Any git command that
touches the rigged .git directory executes attacker controlled
programs. This project reproduces the mechanism with a fully harmless
payload: it writes a local file with system information and nothing
else. No network access. No execution of downloaded code. No data
leaves the machine.

## Why a builder

A git clone never transfers .git/config, hooks, or
.git/info/attributes. Those are exactly the places where the trap
lives. So the repository stores every rigged component as a plain
reviewable file and assembles the armed archive locally with
build-poc.sh.

## Usage

    ./build-poc.sh
    unzip Contract-2026-poc.zip
    cd poc-build
    open contract.pdf

The victim opens contract.pdf, sees a professional looking error
message stating that the document needs the accompanying repository,
and is instructed to run git checkout contract. The clean filter runs
when git inspects the contents of a modified tracked file, so edit any
tracked file first to observe the capture. The post checkout hook runs
on every checkout regardless.

## The PDF lure

contract.pdf is generated by make_contract_pdf.py. It presents a
credible employer header, a red error box titled Unable to Display
Document, and an instruction to retrieve the contract from the branch
named contract. It contains no scripts and no embedded actions, only
text. The lure relies entirely on social engineering, which mirrors the
real campaign where the victim was nudged by a README file instead.

## Artifacts produced on the victim machine

    poc-system-info.txt            system information a real attacker would have obtained
    poc-post-checkout-marker.txt   proof the hidden hook ran

## Attack stages

Stage 1: core.hooksPath in .git/config relocates the post checkout
hook to .git/objects/interrupt/ so it hides among internal plumbing.

Stage 2: .git/info/attributes applies the filter to every file, so a
plain git status pipes file contents through the filter program.

Stage 3: .git/ltr behaves like a working filter and passes content
through with cat, while a debounced background process performs the
action of the real payload. Here that action is writing
poc-system-info.txt with hostname, os, kernel, arch, user and working
directory. In the real campaign the same spot downloads and executes
remote code.

## Defense

Any recruiter archive containing a .git directory is hostile until
inspected. List it with unzip -l and stream single files with
unzip -p instead of extracting. Read branch contents with hooks
disabled using git -c core.hooksPath=/dev/null, or delete the .git
directory entirely. An employment contract needs no repository. Study
unfamiliar repositories only inside a disposable virtual machine or
container. A PDF that demands git commands to display is a lie: no
legitimate document needs a repository to render.

## Ethics

This proof of concept exists to demonstrate and defend against a
documented real world attack technique delivered through fake
recruiter profiles. It contains no malware and performs no network
activity. Use it only for security education.
